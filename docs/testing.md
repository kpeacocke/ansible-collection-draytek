# Testing

## Local checks

Install the development dependencies and collection dependencies from the
repository root:

```sh
python -m pip install -r requirements-dev.txt
ansible-galaxy collection install -r requirements.yml
```

Run the local unit suite, lint and collection build:

```sh
python -m pytest tests/unit
ansible-lint
ansible-galaxy collection build --force
python scripts/project_factory.py local-doctor
python scripts/project_factory.py self-test
python scripts/baseline.py validate
```

CI also runs `ansible-test sanity --docker default -v -- plugins/ tests/`
from a checkout located under `ansible_collections/kpeacocke/draytek`, with
the collection dependencies installed alongside it. Docker and the
Ansible test containers are required for that command.

## Baseline update repeatability

The updater includes the no-op and bytecode fixes from
`kpeacocke/engineering-baseline-template` revision
`b988752d59248f52660bf95421b2d5149100f497`, still labelled baseline 0.5.1.
Same-version catalogue changes must still be applied; the version alone is
not a sufficient freshness check.

Run `python -m pytest -q tests/unit/test_project_factory.py` to exercise both
the installed updater and its catalogue copy. The regression creates an
isolated Git repository, preserves a local workflow override, introduces
generated bytecode in the update source, applies a real same-version change,
commits it, and performs two further updates. Both repeated runs must leave
the index and worktree clean and preserve the state file byte-for-byte.
The scheduled workflow exits before publishing when that index is clean.

## Fixtures and device validation

Tests under `tests/unit/` use sanitised fixtures and mocks; they do not prove
live connectivity or device behaviour. Fixture provenance and hardware
coverage are recorded in the [device matrix](supported_devices.md). Follow
the [fixture contribution instructions](../CONTRIBUTING.md#contributing-drayos-device-fixtures)
before capturing or sharing output.

The AWX playbooks described in the device matrix include a fixture-only check
and a separate read-only live facts check. Run the latter only on an
authorised device, and record its model, firmware, job ID and checked-out
revision. The live check collects sensitive facts with logging suppressed; it
does not validate configuration changes.

The fixture-only AWX playbook runs the full unit suite in a temporary Python
environment. It copies the repository governance scripts, catalogue and workflows
alongside the collection because the unit tests cover those files too. Collection
dependencies are forcibly installed into that temporary layout, even when the
execution environment already has them elsewhere; the isolated Python interpreter
must be able to import them. The temporary layout is removed after the run.

For the live AWX check, supply `drayos_validation_known_host` as an extra variable
containing the router's previously verified public `known_hosts` entry. Its first
field must be the inventory's `ansible_host` (or `[host]:port` for a non-default
SSH port), not a hashed hostname or an entry for another device. Obtain it
from a trusted client or an independently verified source, not an unverified
`ssh-keyscan` result. Never supply a password or private key in this variable.
The playbook installs that entry into the execution environment's SSH trust store
with logging suppressed, and requires host-key checking even when AWX disables it
through its environment. The project's `ansible.cfg` disables automatic trust of
unknown SSH keys for both transport backends. A missing or mismatched key must
fail rather than falling back to an unverified connection. This setup changes only
the job's execution environment, not the router.

Preparation and policy checks are pre-tasks of the device play, with local work
delegated to the execution environment. They still run with a device-only limit,
and any failure stops that host before the facts tasks. Backend-specific
host-key-checking settings are enforced alongside the generic settings; unsafe
extra-variable overrides are rejected rather than silently taking precedence.

## Runtime and SSH backend matrix

CI runs the complete unit suite on these explicit combinations:

| Python | ansible-core | ansible.netcommon |
| --- | --- | --- |
| 3.11 | latest 2.19.x | 6.0.0 |
| 3.12 | latest 2.20.x | 8.7.1 |
| 3.14 | latest 2.21.x | 8.7.1 |

Each row installs both Paramiko and ansible-pylibssh, imports the actual
backend binding, and exercises the netcommon Paramiko and libssh receive
loops. These are offline transport/parser tests, not live SSH handshakes
or a promise about every cross-product of the declared dependency ranges.
Hardware evidence must record the execution environment and selected backend
separately. Missing bindings fail tests instead of silently skipping coverage.

## Approved hostname qualification and recovery rehearsal

**Blocked:** authorised jobs 1946 and 1951 failed temporary-name readback.
The model-specific manual contradicts the current command mapping; see the
[hostname evidence](hostname.md). Do not launch the write playbook until the
mapping is corrected and qualified. The original name was verified over SSH
and HTTPS. Independent HTTPS restoration and live libssh qualification have
not yet passed. Stored write approvals on the inspection template are false.

`tests/awx/qualify_vigor2927lac_hostname.yml` is a separate **write-capable**
playbook. The existing live facts playbook remains read-only. Both share the
same fail-closed key preparation as pre-tasks of their device play, so
device-only limits do not bypass it.

Before launching, an operator must approve the exact temporary name, confirm
a current backup kept outside job output/shared workspaces, and be able to
recover the router independently if both SSH and HTTPS fail. A backup
attestation is not a tested restore. Never perform a reboot, backup restore,
network change or deliberate management interruption as part of this test.

Use the existing inventory/SSH credential and verified public host key in a
dedicated template, limited to `HomeOne`, with verbosity 0, no stored facts,
no schedule and a 900-second job timeout. Required extra variables are:

```yaml
drayos_hostname_change_approved: true
drayos_hostname_recovery_ready: true
drayos_hostname_test_name: HomeOne-test
drayos_hostname_validation_backend: paramiko  # or libssh; binding must exist
drayos_hostname_recovery_rehearsal: false
```

The original name is captured privately and must pass an unchanged check-mode
prediction before writing. The job then checks a changed check/diff prediction,
proves the prediction made no change, applies the temporary name, requires
readback, and proves repeat/check-mode idempotency. An `always` block restores
and rereads the captured original name. Failures remain failures even if
cleanup succeeds; failed cleanup is never treated as successful qualification.

For the independently approved HTTPS rehearsal, set
`drayos_hostname_recovery_rehearsal: true`. Once the job reaches its explicit
180-second recovery window, refresh the existing HTTPS management screen,
change **only** Router Name back to the recorded original name, and submit
the normal UI form. The job must observe the original name over SSH before
its cleanup block. Otherwise it fails and attempts SSH restoration itself.
Never leave the temporary name in place waiting for later approval.

This rehearses an alternative management protocol, not recovery from a dead
router, failed network, reboot or corrupted configuration. Ansible cleanup is
best-effort: job cancellation, execution-node failure or an unreachable
device can prevent it. The named operator must then restore the original
name through the approved management/recovery route.

Record source revision, job ID, model/firmware, execution environment, backend,
individual resource/assertion outcomes and the final restored-name result.
Only delegated controller setup should be ignored when interpreting a job's
overall changed count; the expected temporary router writes are real changes.
