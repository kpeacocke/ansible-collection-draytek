# Read-only TR-069 parameters

`kpeacocke.draytek.drayos_tr069` reads a single leaf or discovers next-level
parameter names over the existing `ansible.netcommon.network_cli` connection.
It offers no setters, persistence commands or recursive value dumps.

```yaml
- name: Read manufacturer privately
  kpeacocke.draytek.drayos_tr069:
    parameter: InternetGatewayDevice.DeviceInfo.Manufacturer
  register: manufacturer
  no_log: true

- name: Discover next-level names privately
  kpeacocke.draytek.drayos_tr069:
    parameter: InternetGatewayDevice.DeviceInfo.
    query: names
  register: parameter_names
  no_log: true
```

## Safety and output

Task-level `no_log: true` is mandatory, including for offline parsing. The module
rejects an unprotected invocation before any device access. Keep subsequent
tasks using registered results private too. Arbitrary TR-069 parameters can
contain passwords and other credentials.

Raw persistent connection logging must remain disabled
(`ansible_persistent_log_messages: false`, the default). The cliconf plugin
rejects these queries before sending a command if that logging is enabled,
including when invoked through `ansible.netcommon.cli_command`.
Do not enable controller/debug logging that records private registered values.

Every successful operation reports `changed: false`, including check mode.
Value queries return `gathered.parameter`, the single-line `gathered.value`,
opaque `gathered.flag` text and boolean `gathered.writable` metadata. The
flag has not been decoded into a data type. Writable metadata does **not**
establish that a setter is safe, implemented or qualified.

Values retain their received case and whitespace; there is no speculative
boolean/numeric conversion. Explicit empty-value framing is supported by
synthetic parser tests only. Empty and multiline values have not been
hardware-qualified; missing or unfamiliar framing fails explicitly.

Names queries require a trailing-dot subtree and return `gathered.parameter`,
`gathered.names` and `gathered.count`. Results must contain unique immediate
children and match exactly one declared count, which can follow the names.
The optional content-length header documented in the vendor example is
recognised, but its byte-count meaning is not qualified and is not used as a
completeness assertion. Unexpected lines, incomplete counts,
duplicate names and out-of-subtree names fail rather than producing a
success-shaped partial list. Pagination is bounded to 64 advances and the
persistent command timeout.

For offline parsing, use `state: parsed` with the same `parameter`/`query` and
the complete response in `running_config`; results are under `parsed`.
No device connection is made. Protect captured output as a secret.

## Evidence and limits

The source catalogue documents `sys tr069 get <parm> [nextlevel]` in record
`209_sys_tr069` (manual pages 877–880). Earlier names-only hardware job 1968
verified complete DeviceInfo, System, Board and SNMP discovery.

Read-only jobs 2065 at `6779b83` and 2068 at `ee75c3e` on Vigor2927Lac firmware
4.5.2.2, using Paramiko and the verified SSH host key, established the
single-leaf response structure: value, blank line, `Flag`, blank line,
`Writable`. All three product parameters returned writable metadata `0`;
the observed flags were `3022` and `9022`. Only redacted structure and
allowlisted metadata were logged, never full responses.

AWX fixture job 2071 passed 262 tests at `b378d0f`. Live module job 2072 passed
all three product-value/metadata assertions, then rejected the names response.
Read-only diagnostic job 2075 at `7d24991` established why: this firmware
returns 18 names followed by their count, **without** the vendor example's
content-length header. LF/CRLF regression tests reproduced that rejection,
and the parser now accepts this observed framing while still requiring exact
count, uniqueness, subtree boundaries and recognised lines.

AWX fixture job [2097](https://awx.ambitiouscake.com/jobs/playbook/2097/output)
passed 271 tests. Live job [2099](https://awx.ambitiouscake.com/jobs/playbook/2099/output)
passed the product value and metadata assertions, complete DeviceInfo names
check, and check-mode equality on the same Vigor2927Lac using Paramiko and the
verified SSH host key. Both jobs ran at `2ee3ba604da10551050f06ef91a814fbbd9fed0d`.
The live job reported one changed task, which installed dependencies locally
in the execution environment; the router reads made no configuration changes.
Earlier jobs 2078 and 2080 did not run because their project update failed.

Other devices and firmware, writable parameters, type conversion, multiline
values and recursive subtree values remain unqualified. Unknown formats fail;
this is not support for arbitrary firmware.
